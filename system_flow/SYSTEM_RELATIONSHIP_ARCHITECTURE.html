⚡ ระบบบริหารจัดการห้องปฏิบัติการพยาบาล (Nursing Lab System)

แผนภาพความเชื่อมโยงทั้งระบบ (End-to-End System Relationship Architecture)

แผนผังแสดงความสัมพันธ์และปฏิสัมพันธ์เชิงสถาปัตยกรรม (Architecture & Operational Matrix) เชื่อมโยง 5 มิติหลัก: ผู้ใช้งานและสิทธิ์ (Roles), ทะเบียนและผังคลัง (Storage Hierarchy), กระบวนการคำขอ (Workflows), ระบบแจ้งเตือนและการสื่อสาร (Notifications), และการกำกับวิเคราะห์ (Audit & Analytics)

✨ สถาปัตยกรรมไร้รอยต่อ: นิสิตยื่นคำขอ → แจ้งเตือนอาจารย์รับทราบ & เจ้าหน้าที่อนุมัติ → ล็อกสต็อกและจัดเตรียมของ → สแกนรับมอบ & คืนด้วย QR Code → บันทึกงบประมาณและเวลาฝึกจริง
VERIFIED BUILD: 62/62 ROUTES
01

มิติผู้ใช้งาน สิทธิ์การเข้าถึง และจุดเริ่มต้น (User Roles & Ingress)

Supabase Auth & RLS
🎓 นิสิต (STUDENT) Ingress

ยื่นคำขอยืมครุภัณฑ์เดี่ยว, ขอเบิกวัสดุ, คำขอเบิก-ยืมแบบรวมชุด (Unified Request), จองรอบฝึกหัตถการ (Practice Booking), สแกน QR ตู้/ห้องดูพัสดุ และรับการแจ้งเตือน

→ Unified Request → Practice Booking → My Bookings
👩‍🏫 อาจารย์ผู้สอน (TEACHER) Reviewer

ตรวจสอบและ กดรับทราบ (Acknowledge) คำขอยืม/เบิกพัสดุในรายวิชาที่ดูแล, อนุมัติผ่านระบบ หรือผ่านปุ่มในอีเมล 1-Click (Email Quick-Action), ดูงบประมาณรายวิชา

→ Approvals Center → Email Quick-Action → Course Analytics
🔬 เจ้าหน้าที่แล็บ (OFFICER) Fulfillment

พิจารณาอนุมัติคำขอ, จ่ายพัสดุ (Check-out/Dispense), สแกนรับคืน (Return), จัดเตรียมชุด Kits, แบ่งบรรจุปลอดเชื้อ (Repack), บริหารห้องและตู้จัดเก็บ, ตรวจเช็คสต็อก

→ Lab Store POS → Repack Room → Storage Location QR
⚙️ ผู้ดูแลระบบ (ADMIN) Control

จัดการบัญชีผู้ใช้, กำหนดบทบาท, นำเข้ารายชื่อนิสิต Bulk Import, กำหนดรายวิชาและโควตางบประมาณ, จัดการระบบสำรองข้อมูล (Database Backup) และสิทธิ์ทั้งระบบ

→ Users Management → Course Config → Audit Logs
02

มิติคลังพัสดุ ผังโครงสร้างจัดเก็บ และชุดหัตถการ (Master Data & Storage Hierarchy)

Inventory & Structure
🏢 ผังห้องและตู้จัดเก็บ (Storage Hierarchy) Hierarchy

โครงสร้างต้นไม้ 3 ระดับ: ห้องแล็บ (Room) → ตู้/โซน (Cabinet) → ชั้นวาง (Shelf) ติดตั้ง QR Code สแกนเปิดดูครุภัณฑ์และวัสดุที่บรรจุอยู่ภายในได้ทันที

→ /storage/room/[code] → /storage/[code] → Items Location
📦 ทะเบียนพัสดุหลัก (Item Master) Prisma Item

แยกประเภทเป็น ครุภัณฑ์ (Asset) ซึ่งมีรหัส Asset Code และ QR Code รายชิ้น กับ วัสดุสิ้นเปลือง (Consumable) ควบคุมด้วย StockLot, Lot No., Expiry Date

→ Asset Code (QR) → StockLots & Expire → Reconcile
🧰 ชุดฝึกปฏิบัติการ (Practice Kits) PracticeKit

มัดรวมครุภัณฑ์และวัสดุสิ้นเปลืองสำเร็จรูปตามหัตถการ เช่น หัตถการฉีดยา, ทำแผล ปลอดเชื้อ ผูกกับรายวิชาหลักสูตร ให้นิสิตเลือกฝึกซ้อมได้ในคลิกเดียว

→ Kit Items Mapping → Practice Booking → Auto-Deduct Stock
🧪 ระบบแบ่งบรรจุปลอดเชื้อ (Repack & Sterile) Sterilization

ตัดสต็อกหน่วยใหญ่ (เช่น สำลีก้อนห่อใหญ่) แบ่งบรรจุเป็นซองย่อย ระบุจำนวนชิ้นต่อซอง, วิธีการอบฆ่าเชื้อ (Autoclave / ETO) และออกรหัส Sub-lot ใหม่

→ Source Lot Deduct → New Sterile Sub-lot → Expiry Tracking
03

มิติกิจกรรมดำเนินงาน วงจรคำขอ และการจัดส่ง (Operational Workflows & Lifecycle)

Workflows & POS
📋 คำขอเบิก-ยืมแบบรวมชุด (Unified Request) Unified

นิสิตยื่นคำขอยืมครุภัณฑ์พร้อมขอเบิกเวชภัณฑ์ในแบบฟอร์มเดียว ระบบผูก ID อัตโนมัติ เช็คความพร้อมของสต็อกแบบเรียลไทม์ ป้องกันการเบิกเกินสต็อกคงเหลือ

→ BorrowRequest → RequisitionRequest → Approvals
📅 การจองฝึกปฏิบัติการ (Practice Booking) Booking

นิสิตเลือกห้องปฏิบัติการ, วันที่, สล็อตเวลา, หัตถการ และชุด Practice Kit ระบบออก Secure QR Token ส่งให้นิสิตใช้สแกนเช็คอินเข้าห้อง

→ Room Slots → QR Entry Pass → Attendance Time
⚖️ ศูนย์พิจารณา 2 ระดับ (Decoupled Approvals) Governance

แยกบทบาทชัดเจน: อาจารย์กดรับทราบ เพื่อตรวจสอบความสอดคล้องกับรายวิชา → เจ้าหน้าที่แล็บกดอนุมัติ เพื่อตรวจสอบสต็อกและความพร้อมของอุปกรณ์

→ Teacher Acknowledged → Officer Approved → Ready to Dispense
🛒 จุดบริการจ่าย-รับคืน (Lab Store POS) Fulfillment

เจ้าหน้าที่สแกนบาร์โค้ดหรือ QR Code เพื่อจ่ายพัสดุ (Check-out) และสแกนรับคืน (Return) ตรวจสภาพชำรุดเสียหาย และส่งต่อไปยังระบบซ่อมบำรุง

→ Barcode/QR Scan → Dispense & Return → Maintenance Ticket
04

มิติการแจ้งเตือนแบบเรียลไทม์ และการนำทางด่วน (In-App Notification & Direct Deep Linking)

Real-Time Center
🔔 กระดิ่งแจ้งเตือน Navbar (Notification Bell) Navbar UI

ติดตั้งมุมขวาบนของ Navbar (ไม่รก Sidebar) พร้อม Unread Badge สีแดงกระพริบ แสดงเวลาแบบมนุษย์เข้าใจง่าย (เช่น "5 นาทีที่แล้ว") และปุ่มอ่านทั้งหมดในคลิกเดียว

→ Background Polling 45s → Window Focus Refresh → Mark Read Optimistic
🚀 ระบบวาร์ปตรงทันที (Direct Deep Linking) Deep Link

คลิกการแจ้งเตือนแล้วมาร์กเป็น "อ่านแล้ว" พร้อมนำทางตรงไปยังหน้าเอกสารที่เกี่ยวข้องทันที: ยืม (/borrow), เบิก (/requisitions), อนุมัติ (/approvals), จองฝึก (/practice/my-bookings)

→ Zero User Confusion → Immediate Action → Status Sync
✉️ อนุมัติผ่านอีเมล 1 คลิก (Email Quick-Action) Email HMAC

ส่งอีเมลแจ้งอาจารย์และเจ้าหน้าที่พร้อมปุ่ม "อนุมัติ" หรือ "ปฏิเสธ" แนบ HMAC Token เมื่อกดอนุมัติ ระบบจะบันทึกสถานะและสร้าง In-App Notification แจ้งนิสิตทันที

→ Resend Provider → HMAC Signed Token → Auto-trigger In-App Notif
⏰ ตรวจจับอัตโนมัติเบื้องหลัง (System Watchdog) Automated

ทำงานเบื้องหลังตรวจจับ 2 เหตุการณ์สำคัญ: ครุภัณฑ์ที่ เลยกำหนดส่งคืน (Overdue) และล็อตเวชภัณฑ์ที่ กำลังจะหมดอายุในอีก 30 วัน เพื่อแจ้งเตือนเจ้าหน้าที่

→ Overdue Borrow Alert → 30-Day Expiry Warning → Direct to Inventory
05

มิติการกำกับดูแล วิเคราะห์ข้อมูล และรายงาน (Analytics, Audit & Governance)

Intelligence
📊 รายงานและสถิติการใช้งาน (Executive Analytics) Dashboard

แสดงอัตราการใช้งานห้องปฏิบัติการ (Room Utilization), สถิติการยืม-คืนตามรายวิชา, การวิเคราะห์การเบิกใช้วัสดุสิ้นเปลืองแยกตามหลักสูตร และพัสดุที่ถูกยืมบ่อยที่สุด

→ Recharts Visuals → Course Cost Summary → Utilization Rate
📑 ตรวจนับสต็อกและปรับยอด (Inventory Reconciliation) Audit

บันทึกประวัติการปรับปรุงสต็อก (Adjustments), สรุปยอดคงเหลือจริงเทียบกับในระบบ, ป้องกันการรั่วไหล และรองรับการส่งออกข้อมูลเป็น Excel รายงานประจำปี

→ Audit Log Trail → Export XLSX Report → Discrepancy Tracking
🛠️ ระบบซ่อมบำรุงครุภัณฑ์ (Asset Maintenance) Maintenance

ติดตามสถานะครุภัณฑ์ชำรุด, ส่งซ่อม, รอบการสอบเทียบ (Calibration), ประวัติค่าใช้จ่ายในการซ่อม และนำพัสดุกลับเข้าสถานะพร้อมใช้งาน (AVAILABLE)

→ Under Repair Status → Cost Records → Re-activate to Stock
💾 สำรองข้อมูลและความปลอดภัย (Backup & Security) Security

ระบบสำรองฐานข้อมูล Supabase PostgreSQL อัตโนมัติ, ระบบเก็บบันทึกประวัติการใช้งาน (System Logs) และการเข้ารหัสรหัสผ่านด้วย Bcrypt มาตรฐานสูง

→ Automated JSON Backup → Session & Token Security → Zero Data Loss

📈 แผนผังการไหลเวียนของข้อมูลและสถานะ (Data Flow & Transition Topology)

ความสัมพันธ์ระหว่างผู้ใช้ (Actors), เอกสารคำขอ (Entities), การจัดสรรคลัง (Stock Ledger) และการแจ้งเตือน (Notifications)
