# แนวปฏิบัติการรักษาความถูกต้องของรหัสอักขระและการเขียนโค้ด

สกิลนี้มีวัตถุประสงค์เพื่อป้องกันปัญหาตัวอักษรภาษาไทยเพี้ยน และการประกาศโค้ดซ้ำซ้อนหลังจากทำการแก้ไขไฟล์

## 1. การรักษาความถูกต้องของรหัสอักขระ (UTF-8 Encoding Policy)
- **ห้ามบันทึกไฟล์โดยไม่มีการระบุ Encoding เด็ดขาด**: ทุกครั้งที่มีการสร้าง เขียน หรือแก้ไขไฟล์ที่มีอักษรภาษาไทยผ่านระบบคอมมานด์ไลน์ หรือสคริปต์ (เช่น Node.js หรือ PowerShell) จะต้องกำหนดรูปแบบให้เป็น UTF-8 เสมอ
  - **Node.js**: กำหนดตัวเลือก `utf8` เช่น `fs.writeFileSync(path, content, 'utf8')`
  - **PowerShell**: ใช้ตัวเลือก `-Encoding utf8` หรือบันทึกแบบ UTF-8 (No BOM) เท่านั้น
- **การกู้คืนอักขระ**: หากพบว่ามีภาษาไทยเสียหายหรือกลายเป็นสัญลักษณ์แปลกๆ ให้ยกเลิกการแก้ไขทันทีผ่าน Git (`git restore`) และตรวจสอบเครื่องมือที่ใช้เขียนข้อมูล

## 2. การตรวจสอบสิทธิ์การนำเข้าและประกาศโค้ดซ้ำซ้อน (Duplicate Code Prevention)
- **ตรวจสอบการ Import ซ้ำ**: ทุกครั้งหลังการแก้ไขไฟล์ ให้ไล่ตรวจเช็คส่วนหัวของไฟล์ว่ามีบรรทัด `import` ตัวเดิมซ้ำซ้อนกันหรือไม่
  - เช่น การเรียกใช้งาน `useAuth` หรือโมดูลไอคอนต่างๆ
- **ตรวจสอบสเตตและฟังก์ชันซ้ำซ้อน (TS2451 / TS2300)**: ห้ามประกาศตัวแปร State (`useState`) หรือ Helper Function ซ้ำซ้อนกันภายในสโคปของคอมโพเนนต์เดียวกัน
- **ตรวจสอบการเชื่อมโยงระบบเดิม**: เมื่อแก้ไขหรือลบ Mock Data เดิมออก เพื่อเชื่อมต่อกับระบบฐานข้อมูล ให้ตรวจสอบว่าได้รักษาตัวแปรแวดล้อมดั้งเดิมของ React Hooks (เช่น `const { profile } = useAuth();` หรือตัวแปร `loading`, `error`) ไว้ครบถ้วน

## 3. ขั้นตอนการตรวจสอบเสถียรภาพ (Verification Routine)
- **การทดสอบ Build เสมอ**: หลังจากดำเนินการแก้ไขไฟล์สำเร็จแล้ว จะต้องรันคำสั่งตรวจสอบการคอมไพล์ผ่านคำสั่ง `npm run build` เสมอ เพื่อให้มั่นใจว่าจะไม่มีคำแจ้งเตือนตัวแปรซ้ำ หรือตัวแปรที่ไม่ได้ใช้งาน (noUnusedLocals)
